# 这份样式表是从哪来的

本目录四个文件是从桌面渲染层**原样复制**过来的，一个字节都没改：

| 本目录 | 来源 | 复制时的 SHA256（前 16 位） | 大小 |
| --- | --- | --- | --- |
| `tokens.css` | `desktop/src/renderer/styles/tokens.css` | `132143CE21951119` | 22603 |
| `base.css` | `desktop/src/renderer/styles/base.css` | `9DF2384AFAF3CD07` | 3163 |
| `primitives.css` | `desktop/src/renderer/styles/primitives.css` | `924CF253734069E7` | 11274 |
| `views.css` | `desktop/src/renderer/styles.css` | `0C99CCB4E5C43BDB` | 270657 |

层叠顺序固定为：**令牌 → 基线 → 原语 → 各视图 → 壳自己的补充**（`main.tsx` 里按这个次序 import）。反了就会互相覆盖，旧渲染层的 `main.tsx:6-9` 也是这个次序。

## 谁是「家」

**本目录是这份样式表的新家。** 桌面渲染层那份进入冻结状态（经典版留档待弃），以后改样式只改这里：

- 改配色、间距、圆角、控件长相 → 改 `tokens.css` / `primitives.css`；
- 加某个视图的布局 → 加 `views.css`；
- 壳自己新增的、旧界面没有的东西（槽位外壳、插件诊断面板）→ 写 `../styles.css`，不要往 `views.css` 里塞。

这么定的理由：旧界面一旦停用，样式改在旧文件里就等于改在一个没人加载的文件里，界面上看不见任何变化，而且不会报错——是最难查的一类问题。

## 为什么整份搬过来，而不是挑着搬

`views.css` 里有九成规则（停靠栏、轨迹页、设置页、文件预览）现在没有对应的界面，属于「暂时不生效」。仍然整份搬，理由有三条：

1. 挑着搬必须知道每条规则「将来属于哪个视图」，判断错了就是几百行的静默丢失；
2. 这份文件按视图分段注释，段落边界清楚，将来搬哪个视图就删哪一段之外的东西，减法比加法好做；
3. 它是本地宿主的静态资产，多出来的字节走环回网卡，代价可以忽略。

`views.css` 里没有裸元素选择器（`html`/`body`/`button` 这类一条都没有，已核对），所以它不会因为「插件画了同名元素」而被误命中；反过来，插件只要用旧版的 class 名，就能直接吃到旧版的样式——这正是我们搬它的目的。
