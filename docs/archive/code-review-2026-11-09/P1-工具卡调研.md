## 0. 一句话结论

**`rows/tool-row.tsx` 的 `ToolRow` 不能删：它不是死兜底，队友运行记录（正文区只读层与右栏子智能体页签）现在就走它渲染。**
04 号文档那句「`ToolRow` 现在的唯一用途是 factory 未注册时的 fallback」（`04-conversation-ui.md:187`）少算了一条路。
真正可以马上删的是**常量副本**（`factory.tsx:97-114`）；`ToolRow` 与 `TraceToolRow` 只能「收」不能「删」——除非先给队友运行记录一条能拿到 Factory 的通道。

三份实现的分工（本次查清）：

| 实现 | 位置 | 现状 | 判定 |
| --- | --- | --- | --- |
| `ToolCard`（Factory 定义） | `src/packages/ui-transcript/ui/tool-card/factory.tsx:170` | 对话页与轨迹页的**主路** | 保留，唯一该长本事的那份 |
| `ToolRow` | `src/packages/ui-transcript/ui/rows/tool-row.tsx:70` | 对话页只是保险丝（不可达），**队友运行记录是活路** | 不能删；可把重复骨架收成一份 |
| `TraceToolRow` | `src/packages/ui-trace/ui/ui.tsx:773` | 轨迹页的保险丝，正常不可达，只在热重装中间帧可达 | 保留独立性没意义；压成一行降级行即可 |

## 1. 注册与取用链

### 1.1 两层：toolview 链 + Factory

「工具卡」不是直接 import 出来的，中间有两层装配：

1. **toolview 链**（谁负责渲染这一条工具调用）：槽名 `transcript.toolview`（`ui-transcript/ui/shared.ts:78`），形态 `kind: 'chain'`，owner 是 `{ entry, storeKey? }`、选举输出是 `matched`（`shared.ts:93-105`）。
2. **Factory**（卡片长什么样）：`TOOLCARD_FACTORY = 'transcript.tool-card'`（`tool-card/factory.tsx:51`），四个局部位置 `preview / statusDetail / bodyExtra / trailing` 加一个普通子槽 `transcript.toolcard.footer`（`factory.tsx:58-94`、`:150-159`）。

### 1.2 注册点（谁登记了什么）

| 登记 | 位置 | 说明 |
| --- | --- | --- |
| Factory 定义 | `factory.tsx:150-159`，被 `ui-transcript/ui/ui.tsx:95` 的 `registerToolCard(ui)` 调用 | 是 `apply` 的**第一条语句**，先于任何槽登记 |
| 主区条目 | `ui.tsx:98-102`：`shell.main` 的 `transcript.flow`，`children: { [TOOLVIEW_SLOT]: 'chain' }` | 有了这条，`TranscriptFlow` 才拿得到 `renderSlot` |
| 内置当选者 | `ui.tsx:103-113`：`TOOLVIEW_SLOT` 的 `transcript.toolview.builtin`，`priority: 100`，`select: (owner) => matchTool(owner.entry.call.name)`，组件 `BuiltinToolView` | 选择器是**全认领**（`matchTool` 永远返回命中），所以链上没人时它一定当选 |
| 只读子流槽 | `ui.tsx:118-123`：`shell.subagent.flow`（`list` 形态，带同一条 toolview 子链） | 这条槽**至今没有渲染方**（见 §3 路径 F） |

`registerToolCard` 只在 `ui-transcript` 里被调用一次（全仓 grep `registerToolCard` 只有 `factory.tsx:150` 定义 + `ui.tsx:95` 调用）。

### 1.4 「没有局部槽位」到底指什么

`renderSlot` 不是可选能力，是槽条目的**装配份额**：条目组件只有在被壳当槽条目渲染时才拿到它（`slots-react.tsx:139-146`、`:159`）。
团队插件是把 `SubagentFlow` 当**普通组件值**渲染的（`ui-team/ui/ui.tsx:662`），所以那份 `renderSlot` 不存在 —— 这就是 `ToolRow` 的活路入口。

## 3. 逐个消费点判断 `ToolRow` 是否会被渲染

1. **`render.tsx:335`**（`?? <ToolRow …/>`）：需要 `renderSlot` 缺席或返回 `null`。
   `renderSlot` 缺席 = `TranscriptFlow` 不当槽条目渲染——它只经 `shell.main` 渲染（`ui.tsx:98-102`），所以不会缺席。
   返回 `null` = `ChainOutlet` 选举无人（`slots-react.tsx:76-77`），而 builtin 是全认领的 catch-all（`ui.tsx:110`），因此支持「注册消失的那一帧」。**结论：只在热重装中间帧可能。**
2. **`tool-row.tsx:53`**（`BuiltinToolView` 的 factory fallback）：需要 Factory 未注册。Factory 与 builtin 在同一个 `apply` 里登记且 Factory 在前（`ui.tsx:95` vs `:103`），要么都在要么都不在。**结论：正常不可达。**
3. **`subagent-flow.tsx:69`**（`props.renderSlot ??` 的右侧）：**队友运行记录两条入口都命中**（`ui-team/ui/ui.tsx:397`、`:718`，两者都走 `:662` 的 `flow.Component`，不带 `renderSlot`）。**结论：活路，不能删。**

补充两条「`ToolRow` 真的被画出来时会发生什么」的细节，说明它不是装饰品：

- 它给队友条目传了 `storeKey`（`subagent-flow.tsx:69` → `tool-row.tsx:76`），展开态按 `${sessionKey}:${at}` 存档，切走再切回仍然记得（`subagent-flow.tsx:31-36` 的 `sessionKey` 就是为它准备的）。
- 它的 context 是 `SubagentFlow` 提供的：`FoldPrefsContext = FOLD_PREFS`、`ShellCwdContext = ''`（`subagent-flow.tsx:72-75`、`:67`）。所以 `useIntendedDiff(call, '')` 里 `cwd` 为空，`toAbsPath` 拿不到绝对路径，推演会回落到「按参数算 diff」那一档（`intended-diff.ts:126-132`）——这是它和 Factory 在队友场景里的唯一实质差别，不是 bug 但值得知道。

## 4. `TraceToolRow` 与 Factory 的差别、以及它该不该独立

`TraceToolRow`（`ui-trace/ui/ui.tsx:773-836`）**已经被 Factory 取代**：轨迹页走的是 `renderFactorySlot('transcript.tool-card', { variant: 'trace' })`（`:640-649`），`TraceToolRow` 只是 `fallback`（`:648`）。两者逐项对比：

| 维度 | Factory `ToolCard`（variant=trace） | `TraceToolRow` | 谁对 |
| --- | --- | --- | --- |
| 点击区 | 只有文字段 `.tool-click`（`factory.tsx:311-334`） | 整个 `.tool-head` 是 `role=button`（`:786-800`） | Factory（`.tool-click` 有焦点圈与手型，`.tool-head` 两样都没有） |
| 状态列 | 局部组件 `TraceStatus`（`ui-trace:751-763`） | 同口径**内联再写一遍**（`:808-819`） | 重复，删内联 |
| 行首栅格 | `.tool-leading` 包住状态点 + 图标（`factory.tsx:325-328`） | 两个 `<span>` 平铺（`:801-802`） | Factory（`--proc-gutter` 竖线对齐，`views.css:9167`） |
| 图标尺寸 | 12（`factory.tsx:327`） | 14（`:802`） | Factory（`styles.css:1178` 的规则按 12 写） |
| 未知名判空 | `match.known \|\| call.name === ''`（`factory.tsx:332`） | 只判 `match.known`（`:806`） | Factory：空名字时 `TraceToolRow` 会印一个孤零零的「· 」（这个坑 `development-log.md:11215` 记过） |
| 卡内调用（PTC） | `SubCallCount` + `SubCallList`（`factory.tsx:343`、`:376`） | 没有 | Factory |
| 落地后的「这次改动」diff | `BodyExtra` fallback = `IntendedBody`（`factory.tsx:374`、`:666-700`） | 没有 | Factory |
| dsh 插件给的 diff 卡 | `dshPatchOf` 并进展开体（`factory.tsx:205`、`:374`） | 没有 | Factory |
| 展开体参数 | 原始 JSON，会改文件的工具改字段表（`factory.tsx:377-405`） | 只有 `prettyJson`（`:824-825`） | 各有取舍，差别是有意保留的证据（`factory.tsx:378-380` 的注释） |
| 吸附栏 / 结果尾巴 / 展开更多 | 都按 `variant === 'chat'` 关掉（`factory.tsx:255`、`:238-241`） | 本来就没有 | 一致 |

**判定：`TraceToolRow` 该「压成降级行」，不该「保留独立」。**
理由有三条：

1. 它承载的外观已经比主路**旧一档**（栅格、图标尺寸、空名字、子调用、diff 全缺），保留它只会在保险丝触发时让轨迹页「跳一张脸」——这正是 04 号文档担心的那种跳变。
2. 它的可达条件几乎不存在：`ui-trace` 把 `transcript` 写进了硬依赖（`ui-trace/package.json:36-38` 的 `client.inject`），启动图里依赖有序（`core/ui-manifest.ts:240-280`），运行时依赖未满足就不 `apply` 并留一行原因（`ui-boot/ui/boot.ts:582-594` → `ui-core/services.ts:134-155`）。也就是说：`transcript` 停用/不在清单里时，**轨迹页自己根本不会装**，`TraceToolRow` 没机会出现。
3. 唯一残留的可达窗口是 `ui-transcript` 热重装：旧登记被释放、新登记还没上，`useFactoryVersion`（`slots-react.tsx:213-217`）会催一次重渲染，那一帧 `definition === undefined`。这个窗口用一行「工具调用 · 名字」的朴素行就够，不需要 60 行完整实现。

**能不能改成复用 Factory 的卡片？** 它已经在复用了（`variant: 'trace'` + `TraceStatus`）。要动的只是 `fallback`：把 60 行实现换成 ~8 行降级行，`TraceStatus` 保留（它是真正按 occurrence 选的局部组件，不是副本）。
