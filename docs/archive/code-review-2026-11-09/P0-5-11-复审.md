- **P0-11：可收（有条件）**。按页签 id 记快照，关页签/淘汰/批量撤三处清理都成立，原始复现

## 二、十个问题

1. **幂等**：整表替换（`transcript.ts:194`），连开三次不翻倍；中间插一笔实时请求，那笔已落盘，下次回填
   补得上，实测总数 = 切走前 + 那一笔。跨进程读半行不崩（`usage-log.ts:456-460` 跳过），但半截行**后面**
   追加的那条会被拼成一行一起丢（分析，未跑）。
2. **口径**：两条路都用 `isPeakHour`（北京时间），差别只在时刻取样——内存取折叠那一刻的 `Date.now()`
   （`transcript.ts:845`），磁盘取落盘那一刻的 `Date.now()`（`usage-log.ts:90`），相差几毫秒，只有恰好跨
   9/12/14/18 点的那几毫秒会不一致，最多一笔，峰谷差价 ≤0.02 元。**判官那笔会多算**：
   `approval/index.ts:1111-1122` 写了磁盘行（`sid` 取 `request.sessionId`，`:1119`），但没走会话 loop，
   也就没有 `agent/index.ts:159` 的 `transcript.emit`，内存桶从没记过它。量级：一次判官输入 ≤4.8 万字历史
   + 2 万字待审参数、输出上限 400 token，**约 0.02～0.09 元/次**；复核 20 次的会话切回来多 0.4～1.8 元。
3. **性能**：每次切会话同步扫全文件，无缓存。实测 100MB（约 50 万行）**137ms**，命中与不命中差不多
   （预筛只省 `JSON.parse`，不省读盘）。TUI 是进程内插件（`tui/index.ts:1`），这 137ms 会卡住终端输入与
   重绘；桌面壳只卡宿主进程。建议加 `(size, mtime, sid) → 桶` 的缓存或按偏移续读（文件只追加），
   重复切会话开销归零。不要求本次实现。
4. **漏的入口**：**分叉漏了**——`forkSession` 换新 uuid（`core/session.ts:1638`），新会话在 `usage.jsonl`
   一行都没有，费用整段不显示，尽管历史里已有几十轮（TUI「撤回上一轮」就走这条，`tui/app/App.tsx:862`）。
   修复前也这样，不是退步。导入 dsh 会话**这个入口在仓库里不存在**（只有 `core/migrate.ts` 迁配置）；
   删除会话后重建拿新 uuid，不会捡旧账；session-search 不自带打开逻辑，最终都汇到
   `runtime.openSession`（`packages/runtime/index.ts:125`）→ `ctx.session.open` → `dsc/session-open`，已覆盖。
5. **测试有效性**：`session-cost-restore-check.mjs` 的 28 条**全部按 `.ts` 源码加载**（自建 resolve 钩子把
   `@pneuma/runtime/*` 与相对 `.js` 映射到 `src/*.ts`），一条都不读 `lib/`；但它用假会话对象直调 handler，
   没走真实 `Session.load`、没测跨进程半截行、没测性能，也没有「磁盘有、内存没有」的判官样本，
   所以 P-2 它抓不到。`context-usage-restore-test.mjs` 运行时读 **`lib/` 旧产物**（`:87-88`），末尾 4 条断言
   读源码；21/21 只证明上下文回填老路径没坏，本轮的收费回填它一条都不断言。
6. **用户语义（`setDockFileView`）**：与 2026-11-08 那版一致——先开预览页签、再挂快照，参数不变
   （`dock-state.ts:364-373`）。同文件已有预览页签时**复用**（`dock-model.ts:387` 全布局按路径去重），
   快照记在复用的那张页签 id 上，路径相同，不会张冠李戴。但复用有次生问题：从文件树点开同一文件
   （`setDockPreview({path})`，`dock-state.ts:281`）不清旧快照，页签头上还挂着上一刀的 `+N/−N`（P-3）。
7. **页签 id 复用**：`makeTab` 的 id = `t` + 36 进制毫秒时间 + 进程内递增序号 + 0～1295 随机数
   （`dock-model.ts:302-308`），进程内绝不复用；重启后 `patches` 本来就空，撞上也读不到旧快照。浏览器页签的
   id 由桌面侧发号（`dock-state.ts:210`，形如 `agent-N`），前缀不同。存档不校验 id 唯一
   （`dock-model.ts:698-736`），同一 id 出现两次才会共用快照，属坏档。
8. **多窗格**：`openPreview` 是**全布局**去重（`dock-model.ts:387` 用 `flatMap` 扫所有窗格），同一文件左右
   两格各一张开不出来；只有 Git 面板拼的正斜杠路径与文件树的反斜杠串不一致，才会同一个文件两张页签
   （`development-log.md:15729-15731` 已记为已知边界），它们 id 不同、快照各记各的。`forgetDeadPatches` 的
   live 集合**不是全布局**，只算当前 `surface`（`patch-sources.ts:59-70`），会误删还活着的——见 P-1。
9. **淘汰与批量撤**：`PREVIEW_MAX` 淘汰发生在 `modelOpenPreview` 里、包在 `mutate` 内，清得掉
   （`dock-state.ts:101`，探针第 4 节实测）；`pruneDockKind` 清当前布局（`:251`）；插件停用经
   `subscribeDockKinds → pruneDockKind`（`:222-225`）同一条路。缺口在 `pruneDockKind`：它把**每个会话**的该类
   页签都撤了（`:241-245`），却只对当前 `surface` 清快照——修 P-1 时要一并改成按全部布局算。
10. **测试有效性**：`dock-patch-invalidate-check.mjs` 只跑 `patch-sources.ts` 与 `dock-model.ts`，`dock-state`
    的接线**只有 3 条正则断言**兜着（`:202-218`），`tabIdOf` 一次没被执行；第 5 条还把「切会话后旧 id 全清」
    钉成期望行为，等于把 P-1 当正确语义。`ui-status-panel-test.mjs` 抽查 5 条静态断言与真实代码一致
    （`forgetDeadPatches(` 恰好 3 处、`<PreviewBody tabId={tab.id} …>`、`patchSources` 五个导出、
    `onOpenFile={(file) => openFileView('untracked', file)}`、`useDockPatchSource(tab.id)`），但
    `dockState.includes('() => null')` 这类短串近乎恒真，`=== 3` 的数量断言也脆。

## 三、真问题

**P-1（P0-11 退步，建议本轮修）** `ui-dockkit/ui/dock-state.ts:89` + `ui-dockkit/ui/patch-sources.ts:59-70`
- 现象：切到别的会话时，`setDockSession` 用**新布局**算 live 集合，另一个会话里仍开着的页签 id 全算「死」。
- 触发：会话 A 开着补丁页签或带「改动」的预览页签 → 切到 B → 切回 A。
- 后果：页签还在（布局按会话存档，`dock-model.ts:754-768`），diff 没了——补丁页签显示「补丁已过期」，
  预览页签的「改动」按钮消失。修复前按路径记，切回来还能看，所以是退步。
- 建议：live 集合改成**全部会话布局**里的页签 id（`Object.values(surfaces)`），`pruneDockKind` 的清理同步改。
  页签 id 不会跨会话重复，放开不会串台。置信度：高。

**P-2（P0-5 口径不一致）** `packages/approval/index.ts:1111-1122` 对 `packages/agent/index.ts:110-122,159`
- 现象：判官请求按会话 sid 记进 `usage.jsonl`，但没有对应的 `transcript.emit`，内存桶从未收到它。
- 触发：任一走 AI 复核的工具调用之后，切走再切回该会话。
- 后果：状态栏费用比切走前多出判官那几笔（0.02～0.09 元/次），用户看见数字跳一下。
- 建议：给 usage 行/事件加来源标记（如 `k: 'judge'`），回填时只折会话 loop 的行。**别**直接给判官补发
  `transcript.emit({type:'usage'})`——那会顺带灌高「本轮 token」和上下文占用（`transcript.ts:836-842`）。
  置信度：高。

**P-3（P0-11 残留）** `ui-dockkit/ui/dock-state.ts:281` + `ui-preview/ui/ui.tsx:112-113`
- 现象：`setDockPreview({path})`（文件树）复用已有预览页签时不删该页签的旧快照。
- 触发：第 N 轮从改动卡「审查」打开 `foo.ts` → 第 N+1 轮从文件树点开同一个 `foo.ts`。
- 后果：页签头上仍是上一刀的 `+N/−N`，点「改动」看到旧 hunks，与 P0-11 同类，只是不用关页签。
- 建议：不带 patch 且复用了已有页签时顺手 `forgetPatch(tabId)`，或给快照带轮次/时间戳比新旧。置信度：高。

**P-4（性能）** `core/usage-log.ts:439-512`：每次切会话同步全扫，100MB 实测 137ms（约 1.4ms/MB），TUI 进程内
会卡输入。建议按 `(size, mtime, sid)` 缓存或按偏移续读。置信度：高（实测）。

**P-5（边界，不要求改）** `core/session.ts:1638`、`tui/app/App.tsx:862`：分叉/撤回拿新 uuid，`usage.jsonl`
没有它的行，费用整段不显示。钱真花过，只是不归到新会话名下；要修得复制来源会话的行或按 `forkedFrom` 回查。

**P-6（边界，分析未跑）** `core/usage-log.ts:452-460`：半截行不在文件末尾时，紧接着追加的那条会被拼成一行
一起丢。一次崩溃丢一条，与 `readSessionUsage` 老行为一致。
