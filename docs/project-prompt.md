# 项目提示词

> **迁移**：复制到目标仓库根目录，命名 `AGENTS.md`；`CLAUDE.md` 用符号链接指过来，别维护两份。只填 §1 每处【】，其余照用。
> **自检**：全文 ≤2000 字；§1 还剩一个【】，就是没装好。

## 1 这个仓库是什么【填空】

- 一句话：【项目名】做【什么事】，入口在 `【路径】`，改 `【路径】` 之前先读 `【文档】`。
- 三层：【内核】跑在【进程】里，【模块】被它调用，【界面】只做展示。
- 命令：装 `【】`；改完跑 `【】`；只跑一条用 `【】`；全量 `【】` 归 CI，本地不跑。
- 版本：根清单、子包清单、git tag 三处数字必须一致。

## 2 两种指令，别混

- **嘱咐**（本文件、prompt、skill）：模型通常照做，没有保证。
- **强制**（hook、deny 规则、脚本、CI）：每次必执行，不看模型心情。
- 一条规则加粗三遍还不听，说明它属于强制，搬出本文件。
- 关于仓库的知识只写三样：读代码读不出来的、会误导人的旧模式、已经纠正过两次的事。架构和目录不用写，它自己会读。

## 3 五道闸

1. **看现场**：`git status --porcelain`、`git branch --show-current`、`git log --oneline -5`。有别人的在途改动，先读再动。
2. **出方案**：选项、代价、推荐项、不做会怎样，四栏缺一栏算没交。需求不清先问；猜的地方单列一行「这是猜的」。
3. **等批准**：用户说「动手」之前不写码，也不派实现型子代理。
4. **拆批**：三步以上先列清单，做完一步立刻改状态；批次按「能独立验收」切。
5. **交付**：先自证，后交接。没跑就写「没跑」，跑挂写 FAIL 条数与原因。

## 4 判据：话要能验

| 你说 | 我要看到 |
| --- | --- |
| 读过代码 | `文件:行号`，贴不出来就是没读 |
| 查过了 | 查不到就直接写「查不到」，不写「应该是」 |
| 验过了 | 命令 + 末尾 10 行真实输出 |
| 改完了 | `git status --porcelain` 只剩该改的文件 |
| 全绿了 | PASS / FAIL 数字 + 没做到的地方 |

「全部通过」四个字什么都不是。证据读起来比我自己重跑一遍快，才叫证据。

## 5 验证面：不全量

- 按改动面挑：改界面跑界面检查并**自己看截图**；改内核跑单测与类型检查；改文档跑文档门禁；改发布脚本就干跑一遍。
- 派出去的活回报三样：跑了哪几条、为什么这几条够、哪些没跑。
- 证据配不上改动面，等于没验证。
- 全量归 CI。本地重复跑已通过的检查，不加信息，只加时间。

## 6 会话与派活

- 一个会话一件事，换任务先清上下文。第一个提示词最值钱：点名文件、症状、什么叫「修好」。
- 派活写清六样：角色、任务、参考源码、**可写白名单 + 禁改黑名单**（越界即失败）、产出格式、验收命令。
- 并行时契约文件冻结，谁都不许改；要加字段先报。
- 长任务跨轮用目标续跑，验收全绿才收，不中途宣布完成。
- 收尾写交接：目标、已提交（commit 号）、未提交（文件）、跑过 / 没跑过、剩余阶段、待拍板的问题。

## 7 被拦、卡住、危险动作

- 破坏性操作（递归删除、强推、重置、删表）先说影响范围与回滚方式，再说做不做。
- 发现越界改动，先回退再继续，不在脏工作区上叠。
- 命令被沙箱、权限、网络拦住：贴原始报错，用**最窄**的授权重试一次。不许改测试、改检查脚本、换条路绕过去。
- 同一件事失败两轮就停，用三行报上来：试了什么、卡在哪、需要你给什么。
- 查不到就说查不到。「大概是」「一般来说」「按惯例」都是没查的伪装。
- 不读、不复述密钥；不把本地配置和环境变量贴进对话。

## 8 提交

- 前缀用 `feat` / `fix` / `docs` / `chore` / `refactor` / `test`；标题写做了什么，正文写为什么。
- 一次提交只做一件事。杂务、内核、界面、文档分开提，别混成一坨。
- 提交前自己看一遍 `git diff`；没让你推就不推。

## 9 这份文件怎么改

- 一条一行，能删就删。新增一条先问：读代码能不能得到？能，就删掉。
- 超字数按顺序处理：搬家到子树文件 → 压缩 → 抬上限，并在提交里说明理由。
- 规则要配门禁：写了「一段一行」就上检查脚本，写了「不许断链」就上链接检查。没门禁的规则会慢慢变成摆设。
- 流程变了就同批改文档；文档和代码不同批交，等于没交。
