# checkpoint（回合快照）

一句话：checkpoint 包在每个回合开始前与收工后各拍一张影子 git 快照，仓库放在 `~/.dsc/checkpoints/`，不碰用户工作区里自己的 `.git`；`/checkpoint restore <回合>` 把工作区退回该回合开始时，同时保住用户自己的手改。**只撤这一回合的改动**：之后回合又改过的同一文件、或模型新建/删除过而用户又动过它，按冲突处理，不自动覆盖。

## Model Experience（模型体验）

- 不注册工具、不写系统提示：模型看不到快照，也拿不到快照内容；它照常读写工作区。
- 回合开始与结束各拍一张（`index.ts` 的 `dsc/turn-start` / `dsc/turn-end` 两个监听），回合号存在影子目录的 `state.json` 里，每回合显式 +1，不从消息数推算（压缩会改消息数）。
- 快照是旁路：同一时刻只跑一张，撞上了就跳过并记一条 debug；任何失败都不会让回合失败，会话流里最多提醒一次。
- 影子仓库超过设置的上限后自动停用，并往会话流说一次；模型与用户都会看到那一句，之后 `/checkpoint` 里仍能查到已有快照。
- 用户敲 `/checkpoint` 时才会看到仓库路径、回合数与占用。`/checkpoint restore <回合>` 只动「这一回合 pre 与 post 之间有差异」的路径：用户没动过的写回起点版本（那时不存在就删掉），用户已经改回起点的跳过，其余做三方合并；任意一处冲突就整次不写盘，并在会话流里列出冲突路径（最多前 10 条）。还原前先拍一张 `dsc/manual-restore-<时间戳>`，还原本身还能再还原一次。

## Known Limitations（已知限制）

- 读不受限：`git add -A` 会读工作区里所有没被 `info/exclude` 排除的文件（`node_modules`、`dist`、`.git`、`<DSC_HOME>` 等除外），不按内核的读禁清单过滤；快照只落在本机 `~/.dsc`。
- 不覆盖 bash 直接改写但未提交的中间态：一个回合里连续改十次文件，也只有回合前、回合后两张快照，中间那九次没有单独记录。
- 单个文件超过 5MB 就不进快照：建仓时扫一遍，把超大的逐条写进 `info/exclude`（之后一直跳过）。为什么要有这条——`git add -A` 会为每个候选文件算哈希，1GB 的安装包能让首次快照卡十几秒。5MB 以内的二进制按原样存、不压缩；仓库占用超过上限（默认 512MB）就整体停用。
- 还原按「整文件」判：一份文件里模型改第 1 行、用户改第 5 行可以合并；两边改同一段就是冲突，此时整次还原一个文件都不写（半写的工作区比不还原更难收拾）。
- 二进制、超过 10MB、符号链接、以及「模型新建或删除过、用户又改过它」的路径一律算冲突，不做文本合并；用户没动过的二进制文件仍会按字节整文件写回起点版本。
- 还原不碰未跟踪且模型没碰过的文件，也不做 `reset --hard` / `clean`：服务器上没有额外动作，工作区里被 `.gitignore` 或影子仓库 `info/exclude` 排除的目录根本不在快照里，也就还原不到。
- 只拍当前会话的回合：回合事件带别的会话归属时直接跳过（`inject` 里没有按 id 找会话的服务），后台会话的回合不会在这里留下快照。

## 行与开关

- 行 id `checkpoint`，包名 `@pneuma/checkpoint`，order 335。
- resolution 是 overridable；默认开：cordis.patch.yml 里没有 `disabled`。
- inject 四个服务：`session`、`commands`、`settings`、`transcript`；设置分区 id `checkpoint`，`/checkpoint` 命令支持 `status`、`list [条数]`、`restore <回合>`。
- 影子仓库的路径口径在 `shadow.ts` 的 `shadowRoot()`：`<DSC_HOME>/checkpoints/<目录名>-<路径 sha1 前 8 位>`。
- 还原的判定与落盘在 `shadow.ts` 的 `restoreTurn()`：先算出全部判定，只有零冲突才写；写盘内容一律来自快照树（`read-tree` + `checkout-index` 取到临时目录），不经过标准输出。
