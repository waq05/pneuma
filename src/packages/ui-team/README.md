# ui-team（子智能体界面半）

一句话：给状态面板「子智能体」区供名单（3 秒轮询写共享席位），并给顶栏递「父会话 / 队友名」面包屑；点一行由宿主打开**队友那条真会话**（2026-11-19 起：顶栏、页签、消息流、输入框、状态栏全与主会话同一套，收工的可续接队友由宿主先按冻结工牌复活）。另外报名右侧栏的子智能体页签（只读重放）。**标题旁不再有按钮与名册模态**——成员只在状态面板列一次；任务那些事归状态面板的「共享任务」区（数据面在宿主包 `subagent`）。

## Model Experience（模型体验）

- 不注册工具，也不贡献提示词（index.ts:31；ui/ui.tsx 只有槽条目、服务与 dock 页签三类注册）。
- 名册来自界面通道 `listTeammates`：常挂载的那条目录每 3 秒轮询一次写进共享席位，页面不可见时停下（ui/ui.tsx:120-160）。
- 停用后模型侧不变，少的只是名册席位、面包屑与页签；状态面板退回它自己的 5 秒轮询。

## Known Limitations（已知限制）

- 名册按 `sessionId` 过滤本会话；别的会话派出的**不列、不给入口**（2026-11-08 起跨会话折叠组已删）。
- 点一行走宿主的 `openTeammate`（2026-11-19）：正文区打开的是它自己那条真会话。**可续接**的队友（本进程还活着、或收工后被复活）在输入框里直接说话；一次性的、复活失败的（角色定义没了、文件被别的窗口占着）只有历史，输入区会换成一说明行（`status.acceptsInput === false`，照 dsh 的 SubagentReadOnlyComposer）。
- 收工队友的「复活」在宿主侧发生（`packages/subagent` 的 `reviveTeammate`）：按名册里冻结的工牌与角色说明书重建一份循环，所以角色文件后来改过也不会改变它的行为；角色文件与冻结点都没有时不复活，按只读打开并说一句原因。
- 「移除」在状态面板行尾（收工的行才有）：删名册记录与运行记录文件，名字随之释放。
- 名册靠 3 秒轮询，页面不可见时停发，回来可能看到过期名单。

## 行与开关

- 行 id `ui-team`，包名 `@pneuma/ui-team`，order 365（package.json:2、15）。
- resolution 是 overridable（package.json:16）；默认开，cordis.patch.yml 里没有 `disabled`。
- `dsh.client`：platform `pneuma`、api `^0.9.0`，没有 phase 与 inject（package.json:20-24）。
- 宿主半 inject 零个服务（index.ts:31）。
- 槽条目 `shell.header.lead`、order 20：**只挂轮询与顶栏面包屑，不画可见元素**（order 10 是模式钮，标题旁读作「新会话 · 标准模式」）；另报名一个 `subagent` dock 页签。
- 顶栏面包屑（`shell.teammate.view`）：正文区正看着某位队友的会话时递「父会话 / 队友名」，点左段 `openSession(父会话路径)` 回去；不挂「只读」标（能不能说话由输入区自己显示）。
- 停用后面包屑与队友页签一起消失；状态面板「子智能体」区退回它自己的 5 秒轮询，点行退回右侧栏页签（`openTeammate` 不可用时的兜底）。
